## 0. 前置条件

| 项 | 要求 |
|---|---|
| 环境 | Node ≥ 22；`dsh web` 已启动并加载本插件；浏览器打开 dsh 页面 |
| 代码同步 | 若用 `file:` 本地安装：Windows 先 `Copy-Item lib/* $env:USERPROFILE\.dsh\profiles\web\node_modules\@memef1f1y\dsh-plugin-tts\lib\ -Recurse -Force` 再刷新页面；改完 lib/ 后建议重启一次 `dsh web` |
| 快速确认新代码 | 设置 → 插件 → 语音 → RVC 配置 顶部出现「**RVC 失败时自动改用 Edge TTS**」勾选项 = 已是新版本 |
| 音频 | 系统有声、浏览器非静音；先与页面交互一次（自动播放解锁） |
| RVC（可选但建议） | 本地模型 .pth + `rvc-server.py`（默认 127.0.0.1:4892）——失败场景需要它「在场但可停止」 |

### 如何模拟「RVC 服务不可用」
- macOS 便携运行时：找到运行 `start-rvc-server.sh` 的终端窗口 → Ctrl+C 或关闭窗口。
- Windows：关闭「启动服务.bat」窗口；RVC WebUI 用户：停掉服务/退出 WebUI。
- 确认已停止：设置 → 语音 →「运行诊断」里 RVC 服务 ✗；或 `curl http://127.0.0.1:4892/health` 无响应。
- 测完恢复：重新启动服务 →「运行诊断」全绿。

## 2. 功能验收（真机逐条）

### 组 A：toast 异常提示（建议 #3）
前置：TTS提供者 = 自定义音色（RVC）；「RVC 失败时自动改用 Edge TTS」= 关；RVC 服务**已停止**。

| 编号 | 操作 | 预期 | 必/建议 |
|---|---|---|---|
| A1 | 点任意一条消息的「朗读」按钮 | 屏幕底部弹出红色 toast：`语音合成失败：无法连接本地 RVC 推理服务（http://127.0.0.1:4892）…`；朗读按钮动画复位 | 必 |
| A2 | A1 后等待 / 点 toast 的 ✕ | 约 6 秒自动消失；✕ 立即消失 | 必 |
| A3 | 开启自动朗读 → 给助手发一条带文字回复的消息 | 新回复尝试朗读后弹出同款错误 toast（自动朗读路径的 toast **无**动作按钮） | 必 |
| A4 | 设置 → 语音 → 试听测试 → 点播放（同为 RVC 停止态） | 预览面板内红字提示，**不**弹 toast（面板维持内联样式） | 必 |
| A5 | TTS提供者切回 Edge TTS → 正常朗读一条消息 | 正常出声，**无**任何 toast（不误报） | 必 |

### 组 B：RVC 降级（建议 #1）
前置：同上（RVC 服务停止）。

| 编号 | 操作 | 预期 | 必/建议 |
|---|---|---|---|
| B1 | 复现 A1 → toast 上有「改用 Edge TTS 朗读」按钮 → 点击 | 该条消息改用 Edge TTS 朗读；声音 = RVC「原声音色」（默认 **云扬·男声**，可在 RVC 配置里确认）；无红色错误 toast | 必 |
| B2 | 选一条**长**消息（>44 字）在 RVC 下朗读失败 → 点 toast 动作按钮 | 全文改用 Edge **分块渐进**朗读，出现「第 x/y 段」计数，段落连续无卡顿 | 必 |
| B3 | 设置 → RVC 配置 勾选「RVC 失败时自动改用 Edge TTS」→ 再点消息朗读 | 自动改用 Edge 朗读（同样为本条消息音色=原声音色）+ 黄色 warn toast「RVC 不可用，已临时改用 Edge TTS 朗读」 | 必 |
| B4 | B3 勾选后刷新页面；再点「恢复默认设置」 | 刷新后开关仍勾选（持久化）；恢复默认后回到**关闭** | 必 |
| B5 | 重启 rvc-server.py → 诊断全绿 → 再朗读同一条消息 | 恢复 RVC 音色朗读，不再出现任何降级 toast | 必 |
| B6 | （边界）RVC **分块朗读中途**停掉服务 | 已缓冲段播完即停止 + 错误 toast；**不会**自动续播（设计边界）；点动作按钮可整篇用 Edge 重读 | 建议 |

### 组 E：审批语音提醒（Agent 事件播报，A1 新增）
前置：设置 → 插件 → 语音 → 「事件语音提醒」**开启**；TTS提供者任意（播报固定走 Edge TTS）。
> 触发审批事件的方式：与助手对话时触发一次需要批准的权限决策（如让助手执行一个会被
> 沙箱要求确认的命令/工具）。审批事件由 Host 订阅 `session/event` 火线摄入。

| 编号 | 操作 | 预期 | 必/建议 |
|---|---|---|---|
| E1 | 触发一个审批请求 | 以提醒音色（默认晓萱）播报「需要审批，…」，**打断**当前正在朗读的内容 | 必 |
| E2 | 同一审批请求再次出现（重放/去重） | 只播报一次（按审批 id 去重） | 必 |
| E3 | 空闲时收到审批结果（勾选「审批结果」） | 播报「审批结果：已批准/已拒绝」；**不打断**正在朗读的内容（空闲才播报） | 建议 |
| E4 | 不勾选「审批结果」仅勾「审批请求」 | 结果事件不播报、请求仍播报 | 建议 |
| E5 | 刷新页面后触发新审批 | 不重播刷新前的旧提醒（首次轮询基线同步）；新审批正常播报 | 必 |
| E6 | 关闭总开关后触发审批 | 不播报任何提醒 | 必 |
| E7 | 播报时 RVC 服务停止/故障 | 播报仍正常（警示强制 Edge TTS，不依赖 RVC） | 建议 |
| 范围 | 任务完成播报 | **不在本期**（dsh-jobs 无插件可观察的会话事件通道，二期接线） | — |

## 4. 声明与限制

- **无独立 HTML**：插件 UI 由 dsh web 宿主注入，无法脱离宿主做 headless 截图对比；中英文布局仍按 README「Known limits」真机目测。
- **分块中途失败不自动重启整任务**（设计边界）：自动降级只覆盖「发起朗读时」的失败；分块播放中途的失败 = 停止 + 报错 toast，用户可一键整篇改用 Edge 重读。
- **自动降级默认关闭**（隐私设计）：RVC 宣传"全本地、音频不上传"；自动降级会把文本发送给微软 Edge 在线端点，需用户显式开启。
- **审批播报走 Edge TTS**：提醒文本（含审批工具名/原因）会发送给微软 Edge 在线端点合成；与 RVC 隐私承诺分离，故默认关闭、开启时设置面板有说明。
- **en 界面错误文案**：host 侧错误保留中文兜底文案 + i18n 标签，极端版本不匹配时 toast 内容可能显示中文兜底（既有行为，非本次回归）。
